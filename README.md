# ALU Regex Onboarding — Data Extraction & Secure Validation

**Author:** Ganza Prince
**Role in the scenario:** Junior Frontend Developer processing raw text returned by an external API.

## What it does

`src/main.py` reads `input/raw-text.txt` (a realistic, messy support-ticket
export) and:

1. **Extracts four data types** using regex:
   - Email addresses — general, plus three ALU-specific sub-types
     (`@alueducation.com`, `@alumni.alueducation.com`, `@si.alueducation.com`)
   - Credit card numbers (validated with the Luhn algorithm, not just shape)
   - URLs
   - Phone numbers
2. **Validates** input instead of trusting it — malformed/spoofed emails,
   invalid card numbers, and placeholder numbers are excluded.
3. **Detects unsafe/malicious content** — script injection, SQL injection,
   path traversal, template injection, and credential-embedded URLs — and
   excludes anything on an affected line from the results rather than
   processing it as real data.
4. **Masks sensitive data** — card numbers and email local-parts are masked
   before they are ever printed or written to disk, so raw sensitive values
   never appear in logs/output.
5. **Outputs**:
   - A console summary (counts + which lines were flagged unsafe, and why)
   - `output/sample-output.json` — the full structured result set

## How to run it

Requires Python 3.8+ (standard library only, no extra installs needed).

```bash
cd alu-regex-data-extraction_pganza-stack
python3 src/main.py
```

This will regenerate `output/sample-output.json` from `input/raw-text.txt`.

To test against your own text, replace the contents of
`input/raw-text.txt` and re-run the command above.

## Design notes / security considerations

- **Regex validates shape, not truth.** A string that looks like a credit
  card isn't necessarily one — every card candidate is additionally checked
  with the Luhn checksum before being accepted.
- **ALU email sub-domains are anchored with `$`** so a spoofed or lookalike
  domain (e.g. `fake-alueducation.com.evil.net`) cannot be miscategorized as
  an official ALU address — it still gets extracted as a general email, but
  never trusted as ALU-affiliated.
- **Unsafe lines are excluded wholesale from URL extraction**, not just
  pattern-matched — a benign-looking URL sitting inside a `<script>` payload
  is not treated as safe data just because the URL substring itself parses.
- **Nothing sensitive is ever printed or written unmasked.** Card numbers
  show only the last 4 digits; email local-parts are partially masked.
- **This is not a full security system.** It demonstrates defensive
  thinking (don't trust input, don't leak sensitive data, don't execute or
  reproduce malicious payloads) as required by the assignment — it is not a
  substitute for a production WAF, input-sanitization library, or PCI-DSS
  compliant payment handling.
